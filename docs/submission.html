Submission guide

Submit one result file per assistant configuration, together with the corresponding execution traces.

Release status. The submission format and file validator are available. Public simulator packages, end-to-end evaluation instructions, and automatic score verification are not yet released. A valid result file is not a verified leaderboard result.

1. What to submit

A result manifest: my-model.json
Identifies the model version, the benchmark version, and every episode’s trace file and SHA-256 hash. The manifest is a JSON index—not a table of claimed scores.
An archive of execution traces
Include the original JSON record for every episode, including failed and timed-out episodes. Retain actions, observations or their references, dialogue, event outcomes, and any engine or judge outputs in the original records. Include referenced assets needed for review; do not substitute a manually written score summary.
Reproduction details in the pull request
Provide engine, user-harness, prompt, and judge versions; model/API revision; inference settings; latency configuration; and run identifiers or seeds. Explain how reported scores and event-coverage counts were obtained.

Do not upload credentials or identifiable human-participant data.

2. Which episodes and runs?

Use the same case–persona pairs in each of three independent runs. A full submission contains nine engine/run entries and 945 episode records.

benchmark_version
Use ive-v1.
model
Provide a model name, a stable checkpoint or API revision, and one family: Frontier API, Streaming API, Open non-streaming, or Open streaming.
runs
For each engine, include run IDs 1, 2, and 3. Each entry lists that run’s complete episode cohort.
trace_uri
A relative file path inside the extracted trace directory—not a URL or an absolute path. You may choose your own directory structure.
trace_sha256
The 64-character lowercase SHA-256 hash of the exact trace-file bytes. Regenerate it if the file changes.
demo_only
Marks this example as partial. Omit this field for a complete submission; full validation rejects demo_only: true.

4. Generate and validate the manifest

Clone the release repository. If your trace files follow the structure above, the helper generates the manifest and computes their hashes:

python ive-source/tools/create_manifest.py \
  --traces ./my-traces \
  --name "My assistant" \
  --family "Open non-streaming" \
  --revision "checkpoint-or-api-version" \
  --output my-model.json

python ive-source/tools/validate_submission.py \
  my-model.json --full --traces ./my-traces

The validator checks all nine engine/run entries, exact case–persona membership, duplicate records, readable JSON traces, and matching hashes. It does not judge response quality or verify that the claimed model produced the traces.

Check a manifest in your browser

This checks the JSON structure and episode membership only. Your file is not uploaded, and local trace files are not inspected.





5. Submit for review
  1. Add your manifest under ive-submissions/ in a GitHub pull request.
  2. In the pull-request description, link the trace archive and include the reproduction details listed above. The archive must be accessible to reviewers.
  3. File checks run on the pull request. Leaderboard inclusion follows a separate review of traces, evaluation settings, event coverage, and scores.
Do not commit large trace archives directly to the website repository. A file-validation pass alone does not publish a leaderboard entry.
